# 升级前的引用兼容性检查

状态：第十六批本地开发，未发布部署。此模块提供**引用级静态比较**，不是自动升级器、游戏客户端验收或镜像内部结构验证。

## 维护者准备候选版本

保留正在使用的PVF、索引、图片包和应用配置，不覆盖它们。在维护电脑用有权使用的候选PVF建立**新的**索引：

```bash
PYTHONPATH=src .venv/bin/python tools/build_catalog.py \
  /private/candidate/Script.pvf /private/candidate/catalog.sqlite --encoding gbk
```

根据实际PVF编码选择参数。可按[素材说明](ASSETS.md)离线生成候选图片包；不必为了静态检查把候选PVF装到游戏服务器。索引元数据中的PVF摘要来自构建工具，此检查不会重新解析/哈希完整PVF，也不会证明候选文件确实来自某个公开下载包。

将候选索引和可选图片包安装到独立的私有版本目录，root拥有、dnfgm组只读，目录0750/文件0640，运行账号不能改文件。在原有0600私有配置中增加：

```json
{
  "upgrade_catalog_file": "/var/lib/dnf-gm/candidates/example/catalog.sqlite",
  "upgrade_assets_dir": "",
  "upgrade_image_digest": ""
}
```

- `upgrade_catalog_file` 默认空，未配置时网页明确显示未配置，不假装检查通过。
- `upgrade_assets_dir` 可指向含 `manifest.sqlite` 的**候选**图片包目录，不覆盖现有 `assets_dir`。未安装/指纹不符单独展示。
- `upgrade_image_digest` 可填精确 `sha256:` 加64位小写十六进制OCI镜像摘要；不接受 `latest` 等可变标签。它只是维护者声明，模块不拉取或启动候选镜像。
- 设置这三个字段不会改变 `catalog_file`、`assets_dir`、`pvf_sha256`、`image_digest`、写开关或任何游戏数据。常规配置加载只需重启GM，**不重启游戏、mihomo、cliproxyapi或共享Docker**。
- 无新增数据库迁移或权限；依赖合并版已有001–011管理表与SELECT权限。仍按既定192MiB/25%CPU、最多3个MySQL连接部署。

## 网页使用

进入“升级检查”，先核对当前/候选PVF摘要和镜像声明。采集快照过期，或当前配置、索引与服务器摘要不一致时，页面明确提示基线未确认。

“需要复验的能力”按PVF和声明镜像的变化列出邮件、礼包、策略、图标/头像、定时运营、存档、原生控制、封禁等相关范围。**不自动暂停任务，不替你激活候选版本。** 在实际升级维护前，需人工核对已有任务与维护计划；本检查不是停机操作。

引用分类：

| 类别 | 检查内容 |
|---|---|
| 礼包全部版本 | 当前启用版本与历史/停用版本分别标注；比较物品编号、名称、类型、等级、耐久、条目路径和堆叠元数据 |
| 收藏与最近物品 | 保留原PVF归属；没有历史索引时不拿当前名称冒充历史名称 |
| 发放策略 | 显示原PVF下启用/停用；跨PVF不自动复制策略或验证证据，物品也检查候选PVF已有的停用策略 |
| 定时运营 | 解析绑定礼包与具体版本；核对计划保存的PVF和镜像绑定；包含非活动计划供排查，不自动重建 |
| 批量任务 | 核对保存的奖励引用和PVF绑定；不重选玩家、不重新发奖、不改变任务状态 |
| 未提交预览 | 只查现存preview记录与冻结奖励绑定，支持查看原操作；不确认或执行 |
| 当前图片映射 | 检查现有物品映射在候选PVF与候选图片包中的存在/状态，不读取PNG像素 |
| 职业头像映射 | 精确职业/转职/性别映射的缺失与内容摘要变化；通配映射不伪装成相同的精确映射 |

重要说明：

- 堆叠上限变化只是**索引元数据差异**，不恢复PVF发放数量限制。奖励数量仍按既有原生整数边界处理。
- 相同编号不保证是同一物品；类别或条目路径改变时额外比较邮件投递类型。
- 旧任务的版本绑定可能早已与当前配置不同，因此检查保存的绑定，不只看“候选是否等于当前”。缺少绑定、损坏/过大的JSON或异常索引项均显示需要核对，不视作干净记录。
- 礼包本身未保存历史PVF索引；其中“当前”属性是当前索引的比较基线，不是礼包建立时的物品属性证明。
- 图片映射可用不表示PNG存在、像素正确或客户端匹配。实际图片仍需既有图片服务验证。
- 页面每次最多50条，跨页不是同一MySQL快照。切换类型从第一页开始；目标文件/配置/实时摘要变化后旧分页凭据失效，须重新读取基线。
- 后台没有提供修改候选路径、上传PVF、SQL、Shell、镜像拉取、服务控制或自动迁移入口。

## 完整引用报告与离线导出

网页“导出全部引用报告”遍历上述八类引用，以NDJSON逐行输出。MySQL使用一个Repeatable Read一致性快照，两个物品索引和已安装图片清单各自保持只读SQLite快照。末尾检查文件身份是否变化；文件原子替换、读取失败、SQL超时或预算耗尽时不能生成完整结束标记。

- 首行 `type=metadata` 记录比较基线、指纹及范围。
- 中间 `type=reference` 是引用与差异，不包含玩家账号密码、数据库凭据、会话或配置文件路径。
- 末行 `type=complete` 只表示**该引用快照遍历完毕**，带每类已检查/需复核数量，`can_deploy`仍为false。
- `type=incomplete`、缺末行或网络中断均不能当作完整报告。请缩小实例数据量/排查超时后重新检查，不拼接不同快照冒充一次完整导出。
- HTTP整体120秒上限，生成器110秒查询预算；按50条分页，不把全量引用放进内存。慢下载/断开由共享导出响应显式关闭连接。SQLite只读、禁用可信schema、约0.5秒语句预算和小缓存；MySQL沿用已有查询超时。

维护者也可在正确私有配置下导出到一个**新的绝对路径**，便于升级记录归档：

```bash
DNFGM_CONFIG=/etc/dnf-gm/config.json PYTHONPATH=src \
  /opt/dnf-gm/venv/bin/python tools/check_upgrade.py \
  --output /private/reports/upgrade-example.ndjson
```

从源码目录执行，按实际安装调整路径；父目录须预先存在并私有。文件0600，不覆盖已有文件，导出不完整时保留文件并返回非零结果。命令使用原有运行数据库权限，不需要维护数据库root。不应把这些包含私有物品信息的报告提交公开仓库。

## 安装与回滚

升级应用并加入候选配置即可，无独立守护进程、定时任务、数据库DDL或新增游戏授权。本模块不会申请新的192MiB之外资源。生产报表成本仍待低强度验收，本地通过不代表生产性能达标。

回滚旧应用前，若旧版Settings不识别新增键，应从兼容配置中移除三个 `upgrade_*` 字段或恢复旧配置；保留候选文件和私有报告。仅回滚GM应用，不替换游戏PVF、不撤销已发奖励、不删除审计或幂等记录。
