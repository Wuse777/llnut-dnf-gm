# 玩家问题工作台（开发版）

当前仅完成本地实现与隔离验证，未部署生产。此模块面向一个密码登录管理员，不建立玩家自助工单门户。

## 使用流程

1. 在玩家中心点击“备注与问题记录”，继承明确的账号 UID；也可从“玩家问题”进入全局查询。
2. 为账号保存备注和最多10个标签（每个最多24字），或建立账号级／指定角色的问题。角色必须属于该账号。已删除角色可以保留排查记录，但不因此获得奖励写入权限。
3. 按待处理／处理中／已解决筛选；更改标题、说明、分类或状态需要填写处理说明。目标账号与角色不可修改，处理时间线不提供删除。
4. 关联原操作时选择“排查参考”或“已完成的补偿”。只有同账号已提交的余额／邮件／组合奖励可以记为补偿；指定角色的记录还校验角色归属。已有参考可以提升为补偿，不能反向抹去补偿事实。
5. “创建余额纠正草稿”或“创建邮件补偿草稿”带入目标与问题编号，不会直接发奖。填写奖励内容，预览核对当前余额、角色、问题版本及已关联补偿次数，再确认一次。
6. 成功奖励与问题关联在同一 MySQL 连接、同一事务提交。不会因为发奖自动把问题改为已解决，仍须由管理员核实处理结果。

## 草稿与错误

- 必填项提示在字段下方；保存错误出现在对应表单按钮附近。
- 未保存备注不因刷新问题列表或追加处理记录而丢失；切换账号必须先保存或放弃备注。
- 问题修改草稿刷新后仍保留原版本；后台数据变化时不能把旧草稿当作新版本覆盖提交。复制需保留内容后放弃草稿，再按新版本编辑。
- 切换问题、离开工作台或创建补偿草稿前，先保存或显式放弃当前草稿；新问题收起并不等于取消。
- 草稿不保存至长期浏览器存储。关闭浏览器／强制刷新仍可能丢失未提交文字，不能视作自动保存。

## 断线与幂等

每次管理写入使用唯一请求键。请求内容指纹、管理记录、时间线、审计和结果收据一起提交：

- 相同键、相同内容返回原结果；相同键、不同内容拒绝。
- 提交阶段断线显示待确认，浏览器会话存储仅保留原请求编号。重载后只查询该编号，不重放写入。
- 暂未查到收据不证明未执行。保持原编号待核查，不重复建立问题或补偿。当前页面在该请求核对完成前暂停新的管理保存；维护人员需依据原请求编号与管理库核查未决情况，不应直接清除编号并重试。
- 业务奖励继续使用原有操作编号、预览和防重流程；本模块不会绕过测试账号、权限、PVF、资源或余额校验。

关联的补偿次数只表示数据库已提交且与该问题关联的奖励笔数，**不等于玩家领取、游戏内生效或全服补偿统计**。目标名称为记录建立时的快照；补偿时仍重新查询当前目标。

## 安装与权限

先完成001–009迁移，维护者再执行：

```bash
python3 deploy/upgrade-support.py --container '<实际游戏容器>' --mysql-port '<实际容器内端口>' --db-account-host '<现有专用数据库用户host>'
```

该脚本只创建010管理表并授予管理表的必要权限，不激活游戏写入、不给游戏表增加权限、不修改玩家数据、不重启服务。当前合并版健康检查要求001–010。新安装的 bootstrap 会包含010；已有实例不可重复 provision。

- `player_profiles`：账号备注与版本。
- `support_cases`：不可变目标、问题状态与版本、关联补偿计数。
- `support_events`：仅 SELECT/INSERT 的追加式历史。
- `support_links`：问题与原操作的关联。
- `support_requests`：原请求内容指纹与提交结果。

所有表必须 InnoDB；写入前检查迁移与引擎，不使用跨库拼凑的非事务写法。仍使用原数据库连接池，最多3连接，无新后台线程或服务。回滚保留010管理表、事件、审计和收据，不撤销已提交的奖励。

## 验证与边界

隔离 MySQL5.7 测试覆盖管理事务、版本冲突、相同请求并发、真实最小权限、奖励／关联原子性和提交响应丢失。Vue 测试覆盖就近错误、草稿保留、XSS文本转义与只读恢复。`tools/browser-support.mjs` 使用真实本地浏览器和拦截的合成 API 检查桌面／手机流程，不访问生产。

这些证据不能代替客户端领取、余额刷新或线上资源验证。生产部署、完整集成及其他路线图项目仍须继续完成。
