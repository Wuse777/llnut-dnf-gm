# PvE已学技能重置

角色详情 → **维护与排查 → 技能与SP／TP → 已学技能与重置**。与下方的剩余SP／TP设值是两个独立入口。

## 范围与操作

- 查看两套PvE技能树的技能名称、编号、等级及剩余SP／TP。
- 选择技能树一、技能树二或两套，填写原因，预览具体技能列表和点数前后对照，再确认。
- 重建当前职业的初始、转职、当前觉醒及副职业赠送技能；移除自学技能。SP采用当前镜像等级表累加，TP采用原生等级公式，不保留过去人工赠送的额外点数。
- 保留未选技能树、技能指令、付费权益标记、公平决斗存档、历史请求／使用字段；选中树存在有效临时洗点标记时，同步重建该树的临时洗点备份，避免旧技能恢复。
- 不修改职业、等级、任务或装备，不冒充游戏中的在线洗点事件。

既有唯一管理员在「功能与版本」管理「PvE技能重置」开关，全部账号均可选择；没有测试账号限制或必须SSH开启的权限。存档写入仍需管理员在维护中心显式开启维护窗口，开窗会退出游戏组件，请自行安排时机；打开页面和查询不会停止游戏。部署与开发测试不自动开窗。

## 匹配索引

在维护电脑本地对已匹配索引生成一个新副本：

```bash
PYTHONPATH=src .venv/bin/python tools/enrich_catalog_skills.py   /private/catalog.sqlite /private/Script.pvf /private/catalog-skills-new.sqlite
```

工具拒绝覆盖输出，保留原物品及策略、附魔、任务、成长与经验表，仅增加技能规则和版本元数据；公开仓库不包含PVF或实际索引。新索引应逐表核对后原子安装，保留旧副本。

技能规则绑定PVF及当前清风1031原生程序指纹。旧索引仍能用于其他功能，但缺少匹配技能规则时不能执行重置；不是后台权限不足。

## 原子性与排错

- 复用维护许可、快照、预览过期、同连接事务、防重意向和审计，不新增游戏表或改变存储引擎。
- 408字节技能明文使用长度头及zlib压缩；按原生分组而非显示分类放入技能槽，未知／损坏存档不猜测重写。
- 预览签名绑定目标、等级／职业／副职业、两套存档、点数、临时洗点备份和技能规则；变化后必须刷新重新预览。
- 运行账号只新增副职业字段查询与四个技能BLOB列UPDATE权限；无任意SQL、全表写入或游戏重启权限。
- 响应丢失后查询原操作编号，不能自动重放；成功表示存档、快照、审计已提交，**不等于游戏客户端效果已验证**。

## 最小验证

相关纯函数与本地socket-only MySQL5.7合成测试覆盖编解码、默认技能／移除、原生分组、SP／TP、副职业边界、选中树与临时备份、未选树与指令保留、快照／审计／幂等、变更拒绝和失败回滚。前端仅测试相关两组件并构建。不用正式玩家执行重置，也不要求客户端配合。线上只查询已有专用角色的技能和维护状态。
