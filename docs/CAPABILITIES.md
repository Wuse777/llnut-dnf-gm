# 功能、版本与网页权限管理

> 当前安装与启用状态以[实施台账](ROADMAP-IMPLEMENTATION.md)、[README](../README.md)和网页「功能与版本」为准。下列早期本地开发说明保留用于追踪，不表示当前仍未上线；部署成功也不等于游戏内效果已验收。

> **历史开发阶段记录（非当前状态）**：开发状态：本地实现，尚未部署到生产。按2026-11-05所有者的新要求，交付时为唯一管理员开放所有已实现能力，不保留测试UID白名单，也不要求通过SSH编辑配置来开启功能。

## 网页使用

进入“功能与版本”：

1. 查看当前构建源码、管理库迁移、PVF/镜像绑定、图片包和采集时间。
2. 在“管理员功能开关”选择所需功能，或者点“全部开放”；此时只是勾选，不执行游戏操作。
3. 填写原因，核对启用/关闭差异，再确认保存。敏感认证过期时在网页输入管理员密码即可；没有TOTP或额外角色授权。
4. 变更保存到MySQL，带修订号、唯一请求编号和同事务审计。当前后端及单执行器即时读取，不重启服务、不改服务器配置文件。
5. 保存后账号范围为全部账号。公告/踢人自动包含原生会话开关；批量执行器自动包含批量奖励开关。关闭原生会话会同时取消公告/踢人，关闭批量奖励会同时取消批量执行器，勾选列表与确认差异同步显示。开启执行器可能继续执行已确认但尚未完成的任务；不会自动确认新任务，不会重复发送已提交奖励。

已有权限选择不会在应用重启、重复运行升级器时被“全部开放”覆盖。关闭功能不取消已经开始的事务，也不撤销已完成操作。已有操作结果仍可查询；审计中的权限请求编号可在通用“按操作编号核对结果”入口读取，不会变成可再次确认的游戏操作。

## 权限和可运行条件不是一回事

界面分开显示三个事实：

- **开关配置**：管理员是否允许该能力；在网页可调整。
- **当前前提**：迁移、采集、资源、版本绑定是否可确认。此页不代替实际目标/余额/存档/维护窗口/原生协议的逐次校验。
- **人工验收记录**：是否关联当前源码、PVF与镜像的接口或客户端记录。没有记录不阻止管理员启用功能，不把启用记录冒充客户端通过。

私信和角色救援尚未实现的部分明确标为待实现，不显示虚假的“已经可用”按钮。装备维护窗口、原生指纹与运行时能力仍需完成生产适配；这份权限管理交付不是整个GM目标完成的声明。

本页不会开放任意SQL、Shell、文件路径上传或核心服务控制。数据库权限仍采用功能所需表/列，不授予数据库root或读取玩家密码。

## 安装与迁移

新增 `012-capabilities.sql`，只含管理库权限策略、不可变请求收据和迁移版本。应用就绪检查要求001–012全部存在。

安装维护使用 `deploy/upgrade-capabilities.py --container <已核实容器> --mysql-port <实际端口> --db-account-host <已核实主机地址>`。升级器会：

- 创建012表和运行账号所需管理表权限。
- 提前授予已实现装备功能需要的固定存档列UPDATE，不再要求每次在SSH临时开数据库权限；不授权金币、角色任意字段或整表删除。
- 仅在策略修订为0时写入“所有已实现开关开启”及安装审计；保留管理员之后在网页的选择。
- 不发送游戏奖励，不创建定时任务，不打开维护窗口，不停止任何服务。

这仍是部署迁移步骤，由部署者完成；不是要求用户每次启用功能都操作SSH。新实例bootstrap包含012迁移及管理表授权，最终安装仍运行上述能力初始化步骤。

运行时复用最多3连接的连接池，无额外队列服务。既有单工作线程同时承担定时/批量任务，闲置时只观察权限变化，最多每5秒读取策略；确认写操作强制刷新。数据库策略不可读时暂停新的受控写入，登录、查询及结果核对保持独立；恢复后自动重读，不使用不明权限继续执行。

## 结果待确认与回滚

提交响应丢失时保留原请求编号，可关闭确认窗口继续使用其他功能；每5秒只读核对，隐藏页面暂停。不会生成新编号或自动重发权限变更。404表示暂时无提交收据，不能当成成功。服务器按原编号和完整参数防重；同编号不同参数拒绝。

新版回滚检查会拒绝将已经网页管理的权限交给忽略该策略的旧代码，防止旧配置重新生效。应选支持 `web_capability_policy: 1` 的兼容版本或经验证的回移植版本；不能只伪造能力标记。检查失败保留当前源码和数据库，GM保持停止并保留自动恢复禁止标记；核对后人工恢复。不删除策略、审计或收据来绕过。

## 可选的版本绑定验收记录

此项只供展示，不是功能权限门槛。维护者可在私有配置 `capability_evidence_file` 指定一个绝对路径JSON文件，示意结构如下（示例不是实际验收证据）：

```json
{"schema_version":1,"records":[{"capability":"mail","level":"api","checked_at":1793811600,"source_revision":"abcdef123456","pvf_sha256":"<64位SHA256>","image_digest":"sha256:<64位SHA256>","reference":"mail-api-report-01"}]}
```

记录最多64条、文件最多64KiB；同一能力不可重复。源码、PVF、镜像三项必须匹配，dirty或未知源码不继承验收结论。旧记录显示“版本不匹配”；来源仅为短报告编号，不展示本机路径、任意链接或文件原文。`client`明确标作“人工记录：游戏客户端”，不是自动证明。
