# 任务异常中心

> 当前安装与启用状态以[实施台账](ROADMAP-IMPLEMENTATION.md)、[README](../README.md)和网页「功能与版本」为准。下列早期本地开发说明保留用于追踪，不表示当前仍未上线；部署成功也不等于游戏内效果已验收。

> **历史开发阶段记录（非当前状态）**：状态：本地实现，尚未部署。网页入口为“运维诊断 → 任务异常中心”，API 为登录后只读 `GET /dnf-gm/api/v1/task-health`。另有专用凭据保护、仅回环可读的汇总探测入口，不向公网发布；无新增数据库连接池、执行线程或系统服务；仍使用现有最多3个数据库连接和现有资源预算。

## 显示哪些问题

- 奖励目标提交结果待核对，包括任务已取消但结果仍未知的目标。
- 单目标执行超过120秒，或执行状态缺少开始时间。
- 未取消任务中已确定失败的目标。取消任务的已确定失败不持续告警，但取消不抹除历史。
- 定时计划异常，或带错误原因暂停；管理员正常暂停不当作故障。
- 计划超过到期时间120秒未触发。
- `awaiting` / `running` 期次超过120秒未核对结果，不用旧的历史失败期次永远报警。
- 有工作待处理时，执行器被关闭、线程未运行、最近处理失败或长期无响应。
- 最早运行奖励任务的未执行目标游标连续120秒未推进。只观察队首任务，不把排在后面的任务或任务创建时间较早当作停滞。

执行器的“最近执行有响应”只证明程序调用完成，不证明奖励在游戏内生效。一次调用返回无工作也属于响应；业务异常由持久状态单独检查。定时扫描失败不会阻止既有奖励任务执行，两类脉冲分别记录。

## 观察边界与未知状态

页面每30秒查询，隐藏时停止轮询。停滞判定使用进程内单调时钟；重启、队首变化、游标推进或超过90秒没有观察都会重新计时。默认由打开页面触发检查；第二十批已增加可选独立观察器调用同一检查。启用后关闭网页也继续积累观测，配置见[独立告警](ALERTS.md)。只有原队首的未执行目标实际推进后，才把正在运行但未发现异常的任务作为恢复证据；首次观察不伪装为已有推进。

每类候选最多读取51条、显示50条；超过上限明确标记“列表不完整”，不能声称所有任务正常。无问题但证据不完整时为 `unknown`。未超过上限也不代表游戏效果已验证。

快照使用既有数据库连接、只读事务、固定SQL和 MySQL 5.7 查询超时；查询间检查0.75秒软预算，每条SELECT最多150毫秒。不执行全量COUNT、不读取玩家名称、奖励正文、任务JSON或原始错误消息。并发快照不排队，返回繁忙未知；任何查询失败丢弃本次部分结果并清空游标观察，不沿用旧正常结果。

> 超时是保护预算，不是生产P95保证。繁忙或超大管理库可能显示未知；生产资源与性能仍待实测。

## 从异常进入原任务

点击“查看原任务／计划”只执行GET，不启动、不恢复、不重新排队、不发奖。奖励任务存在浏览器未确认提交时优先恢复原任务；定时计划保留尚未核对的旧预览，不用新导航覆盖恢复上下文。

任务列表仍是完整处理入口；异常中心只显示候选，不替代任务分页或完整操作审计。

## 已取消任务的结果核对

原实现同时禁止取消任务重发和结果核对，导致已取消的未知目标无法处理。现在：

1. 已取消任务可以“只核对中断目标”。
2. 同连接按任务 → 目标 → 原操作与审计的顺序加锁，沿用现有核对机制。
3. 原操作与审计均证明提交时记为已提交；没有提交证据且已取得事务锁时记为未提交；证据冲突保留未知并拒绝核对完成。
4. 无论结果如何，任务仍为取消状态，禁止恢复／重新排队；不会发放新奖励。
5. 核对写入管理状态与审计，不改变已发放货币或邮件。

没有一键“重试所有未知任务”，没有因报警自动补发。
