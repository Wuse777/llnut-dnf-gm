## 修复与界面

首轮正常图标只有 44,206 项：少量未使用帧的 1 像素图像位于画布外，导致同 IMG 中的正常帧全部被拒绝。现在全部帧仍校验有界尺寸与载荷，画布放置校验作用于实际选中帧或链接目标；不会裁切、填空或把坏帧标记为成功。修复后新增 22,244 项可读图标。两项实际引用的越界帧保持 unsupported。

覆盖接口只返回受保护图片 URL、尺寸、状态与物品身份，不返回私有路径、IMG 名称或 NPK 来源。覆盖页新增缩略图和剩余缺口数；本样本显示 `>99.9%` 及仍有 6 项不可读取，避免误报 `100.0%`。图片仍懒加载，原邮件数量、金币上限和权限不变。

离线头像映射显式按 UTF-8 读取，避免 Windows 中文系统默认代码页导致来源标签和中文路径解码失败。已有图片接口的 Linux 防符号链接机制保持，不为了 Windows 工具放宽线上文件读取。

## 验证范围

- Linux 受限隔离进程运行三个图片相关文件：**53 passed**，合成夹具，不接数据库；隔离 `/run/dnf-gm`，避免测试误读生产采集快照。
- 本机 Windows 首次运行因 Linux 专用 `fcntl`／`O_DIRECTORY` 和符号链接权限有 6 项环境失败；对应测试已在上述 Linux 检查全部通过，不修改防护实现绕过。
- 前端图片组件及覆盖页 **6 passed**，Vue 类型检查／Vite 构建通过；主 JS 仍约 584 kB，拆包优化留待后续。
- 本地真实素材、合成 API 浏览器检查：桌面列表、详情与 390px 手机抽屉／覆盖明细的可见图像正常解码，无横向溢出，未捕获页面错误；没有玩家数据或业务写入。
- 服务器安装结果另行记录，不将本地图片包构建成功写成已部署或客户端一致性已验收。

## 发布与运行

本批源码版本为 v0.4.1；发布流程生成源码包、预构建网页包及 SHA256SUMS。服务器安装与 GitHub 发布分别核对，不上传私人图片包到 GitHub。游戏客户端逐项视觉验收、角色纸娃娃及精确转职像素头像尚未完成。
