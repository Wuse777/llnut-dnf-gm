# 角色疲劳维护

入口：账号／角色 → 角色详情 → **角色维护**。「功能与版本」页提供 `char-fatigue` 独立开关，不限制测试账号。

## 使用

1. 在维护中心明确申请并开启维护窗口；仅查看角色信息不会停服。
2. 刷新疲劳存档。普通与额外 `fatigue` 是已消耗值，设为 **0** 恢复对应额度，不是设为156。
3. 填写原因，生成预览，核对账号、角色及修改前后值，再确认。
4. 结果未知时只查询原操作编号，禁止自动重发。历史记录在本页可查。
5. 结束维护后游戏重新加载存档。数据库成功不等于已验证客户端效果。

保留 `used_fatigue` 历史计数、两个疲劳上限、疲劳电池和活动字段。缺失状态记录不自动创建。改名与位置救援已有独立入口，见[角色改名](CHARACTER-RENAME.md)及[位置救援](CHARACTER-RESCUE.md)；职业/任务修改仍待适配，不提供任意字段编辑器。

## 固定镜像适配

QF1031 当前角色加载路径从 `charac_info` 读取普通/额外上限，从 `charac_stat` 读取消耗值；退出保存至 `charac_stat`。程序的疲劳检查比较消耗与最大值，扣减消耗函数在0截断。依据为只读结构与程序分析，无运行时注入，无玩家写入试错。源程序SHA-256：`8859c99d8290dc5fb58151444138cf2697b2bfff12d47d6159596a03f20b5261`。程序不进入仓库。

## 事务与升级

- `/api/v1/character-maintenance`（前缀 `/dnf-gm`）：读取角色、预览、确认、取消、历史和结果查询。
- `char-fatigue` 长度兼容现有 `operations.action varchar(16)`，不需要结构迁移。
- 复用维护锁、执行意向、同连接事务、审计与不可变快照。预览绑定角色、完整疲劳快照、镜像/PVF/程序指纹和维护窗口；变化后拒绝旧预览。
- `inventory_*` 账本存放类型化快照：`container=character_fatigue`、slot=0，内容为 `qf1031-fatigue-1` JSON，**不是61字节物品存档**。装备历史按动作隔离，不能用装备恢复入口操作角色快照。根执行器关窗核对不解码存档。
- 增加精确 `SELECT(premium_fatigue)` 和 `UPDATE(fatigue,premium_fatigue)` 权限；不授权修改历史计数、上限、等级或角色名。升级脚本已纳入授权。
- 回滚到不识别 `char-fatigue` 的旧版本前，先在网页权限中关闭此新开关并保存；保留操作、审计及快照，已完成疲劳变更不自动撤销。

## 最小验证范围

隔离MySQL：疲劳事务、历史计数不变、幂等结果、入口隔离、旧快照拒绝、无维护拒绝及中断核对；共享装备事务用例。前端：就地校验、目标和接口正确、响应丢失后不重复提交；TypeScript与构建。未暂停生产游戏，未测试真实玩家疲劳写入。

## 改名适配观察（历史研究）

原生改名除 `charac_info` 外，会通知 guild/monitor 同步公会名称与黑名单，并更新角色/佣兵缓存；好友显示存在通过编号联查名字的路径。生产角色名有唯一索引，编码须保留既有MySQL latin1字节往返规则，不能只按Python cp1252处理。已只读检查相关结构和处理函数，没有发送候选报文或修改玩家。下一步须确认DB中间件的固定更新字段及区服命名空间，再接入维护事务；不把现有疲劳维护当作改名已经完成。原生文件与反汇编证据仅在本地私有目录，不进入开源仓库。

当前改名实现及入口见[角色改名](CHARACTER-RENAME.md)，上述研究记录不是当前功能状态。
