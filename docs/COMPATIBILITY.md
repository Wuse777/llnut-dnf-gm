# 适配边界

## 数据库与运行机制

本适配针对清风 1031 的既有 `d_taiwan`、`taiwan_billing`、`taiwan_login`、`taiwan_cain` 和 `taiwan_cain_2nd` 表；字段参考 `fixtures/game-schema.sql`，该文件仅用于隔离实验库，**不能导入游戏服务器覆盖结构**。管理库迁移只创建 / 更新 `dnf_gm`。

点券、邮件、防重与成功审计在同一连接 / 事务中提交；实际游戏表必须保持已验证的 InnoDB 语义。MyISAM 或修改后的触发器、后台缓存机制均需重新评估。行锁不会自动解决游戏进程缓存覆盖。

在线人数以登录表 `login_status=1` 统计，非连接数；异常退出可能影响此表，需与实际游戏在线情况核对。角色属性来自持久化存档，不等于客户端即时装备加成后数值。

## PVF 与版本绑定

在维护电脑本地执行 `tools/build_catalog.py`；不提供上传完整 PVF 的 HTTP 接口。默认不审核开放任何物品，管理员可以在网页预览并开放普通类型试发，但不能绕过特殊类型、堆叠、耐久、PVF 和目标校验。`tools/enrich_catalog_jobs.py` 可对指纹匹配索引补充职业名称，创建新文件且不改变发放策略。

配置中的 image ID 必须与公开采集器输出一致。指纹漂移 / 状态过期将阻止业务写入。索引中的 SHA 与服务器 PVF 不匹配时仅允许查询。公开仓库不附任何实际 PVF 指纹、游戏索引或审核白名单。

## 邮件与金币

- 物品不超过 20 条，普通装备每条数量 1；材料 / 消耗品受已知堆叠上限约束。
- `gold` 为严格整数，0 表示无金币，范围至 1000000000（10亿）。只在第一条 postal 附件记录写入金币，避免多附件重复附币。应用上限不代表已验证的游戏持币上限。
- 纯金币记录使用 `item_id=add_info=endurance=0`。这通过了数据库与接口测试，**领取机制尚未在客户端验收**。不要将未经验证的大额奖励用于真实玩家。
- 网页区分投递与数据库领取标记，不将“数据库已提交”解释成“玩家已领取”。
- 模板记录物品版本，不保存金币，切换模板时清零另填的金币。

封禁仅管理本应用标记的处罚记录；不覆盖其他来源处罚，不声称踢除已在线玩家。

## 文本与角色存档

中文名称只读解析覆盖已观测到的 UTF-8 字节经 MySQL latin1 / cp1252 存储的情形。未知或损坏字节不伪造正常名称。发送邮件的文本编码与读取分离，不支持的字符拒绝写入，不能随意全库转码。

背包 / 装备是受限大小的只读 zlib + 61 字节槽位解码。损坏、未知容器明确显示未知；没有背包编辑或角色删除接口。

装备锁适配1031的800字节解压存档、100条记录与72小时等待。只允许离线账号将选中的未到期申请时间提前，不删除锁或修改背包；未知格式、在线/未知登录状态、预览后存档变化均拒绝。成功后仍需游戏重新加载处理。锁定编号没有可靠映射到装备名/槽位，不猜测展示。此操作默认关闭，需单独适配并授予 `SELECT(charac_no,item_lock_info),UPDATE(item_lock_info)`，不能授予inventory写权限。
