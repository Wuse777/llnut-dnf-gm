# 角色等级与经验存档核对

## 网页入口与范围

角色详情 → 维护与排查 → **等级与经验**。登录后的管理员可查询所有未删除角色，无新权限开关或测试账号限制。接口为 `GET /dnf-gm/api/v1/characters/{charac_no}/progression`，沿用认证、范围校验、限速与连接预算。没有对应的写接口。

显示等级、选角信息经验（`charac_info.exp`）、角色存档经验（`charac_stat.exp`）、原有符号整数与相同32位数据的无符号表示、PVF参考上下界及进度。两处经验有差异不直接判断损坏；在线角色可能还没有保存最新进度。缺失存档、参考表缺失或不匹配、采集过期均明确提示，不以0或满级代替未知。

## 经验表来源

维护电脑离线运行：

```bash
PYTHONPATH=src python tools/enrich_catalog_progression.py current-catalog.sqlite Script.pvf new-catalog.sqlite
```

输入是当前生产索引的精确副本；PVF哈希必须一致，输出必须为新文件。只新增 `progression_thresholds` 与 `progression_index_version=1`，保留现有物品、任务、职业、图片映射等。禁止把PVF或真实物品索引提交到Git。

适配程序 SHA-256：`8859c99d8290dc5fb58151444138cf2697b2bfff12d47d6159596a03f20b5261`。静态核对原生 `set_level_exp/get_level_exp`：等级1取0，等级2对应数组第0项；`get_level_up_exp` 为相邻累计阈值差。当前 PVF `character/exptable.tbl` 有99个整数项，后段超过有符号32位范围。原生登录区间检查使用无符号比较，所以不应直接将负的数据库表示判断成经验不足。

**参考表不等于运行时完整升级规则。** 未通过运行时内存读取或插件审计证明表始终未经改变；页面明确标为PVF参考。未知下级阈值不等于达到服务器等级上限。历史debug指令的70级限制不作为实际服务器上限。

## 为什么尚无等级写入

静态核对原生 `SetCharacLevel` 还处理两套技能树SP/SFP、职业成长属性、金币加成、职业与地图/副职业相关状态；`_onLevelUp` 另处理活动奖励、任务和相关通知。原生登录检查对超出经验区间的角色存在处罚分支。

因此当前只交付存档核对，**等级／经验维护写入仍未完成**。不能用只更新 `lev/exp` 的按钮宣称完成原生升级，也不额外植入运行时注入、伪造GM身份或发包。未修改玩家等级、经验、技能点、属性或任务。

## 最小验证和回滚

本批只执行3个参考算法测试、前端构建及一次部署后的只读页面/API检查，不跑全量回归，不做玩家写入或停服测试。数据库使用已有精确列SELECT，无新增游戏权限或迁移。只读参考表对旧应用无影响；回滚不删除既有审计、防重及维护会话。生产版本与检查结果见实施台账。
