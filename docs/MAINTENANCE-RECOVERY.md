# 维护中断的网页接续

维护中心新增 **核对中断并继续恢复**。适用范围是原维护窗口已签发，关闭窗口、恢复组件或最终解除冻结/记录完成时中断。不是重新停服，也不是撤销已提交的装备修改。

## 操作

1. 在维护中心查询原申请，查看最近步骤与错误；可先点击只读状态核对。
2. 有可接续记录时点击「核对中断并继续恢复」，核对原申请并勾选确认。
3. 提交后只查询原申请。网络超时不会自动再次确认；需要再操作时先核对上次结果。

恢复不依赖「新维护申请」开关，唯一管理员重新认证后可从网页操作，不需要SSH开权限。每次恢复确认独立审计，绑定原申请、计划指纹和日志修订；相同幂等键不可更换参数。root执行器在动作前持久记录本次恢复意向，重复投递只查询，不再执行。

## 接续语义

- 关窗未完成：核对原窗口与全部已停组件，再关闭原窗口并结算未决管理事务。
- 启动标记：按已观察状态补齐原启动标记；不更换启动脚本或参数。
- 已启动组件：核对程序指纹、PID/进程身份及原启动契约；不重新启动。
- 有启动意向而返回记录丢失：只有实际匹配的运行进程能够证明当前状态时才接续，记录为「中断后核对」，不声称收到了丢失的命令回执。
- 尚未执行的后续组件：按原计划顺序启动，每次先持久记录意向。
- 全部恢复后：核对网关与核心健康，解除原写入冻结，补齐最终维护记录。

仅刷新只读恢复证据不会续期装备写入许可；窗口已关闭/过期时仍不能修改装备。中断或旧过渡观察超时后，监控会重新核对原身份、窗口、冻结及进程，维持网页恢复入口可达，但不把异常状态冒充正常游戏服务。

## 当前边界

**启动意向存在、进程却未运行**时不重发该启动命令，保留冻结并显示具体原因。原维护窗口尚未签发的退出阶段中断、容器重启/身份变化、未计划进程变动或已损坏日志仍不属于此接续流程，不能承诺一键修复全部故障。没有新增任意命令、强制重启或跳过核对按钮。

本批使用隔离数据库及合成组件做最小定向验证；没有在生产停服、修改玩家存档或验证游戏内恢复效果。部署不修改数据库结构/授权，不改变21项功能开关及全部账号范围。回滚前须正常结束当前维护；保留恢复审计、root恢复意向及日志，不删除记录重放操作。

## 2026-11-05 全部写入组件退出后的签发中断

新增覆盖以下三个边界：全部写入组件退出后、会话文件建立前；签发意向已保存但许可未生成；许可已持久保存但签发回执丢失。入口仍为维护中心「核对中断并继续恢复」，不新增权限或要求SSH修改配置。

- 已存在原许可：核对ID、原计划、格式及期限结构，补齐签发记录后撤销原许可；过期许可仍可关闭。不再次签发或延长许可。
- 原许可未生成：记录「放弃未签发窗口／窗口未签发」，只创建关闭凭证并核对管理事务，然后按原计划恢复服务；全过程不创建写入许可。
- 监控实时复核原容器、程序、服务契约、全部已停写入者和冻结代次，使恢复网页保持可达。这是只读恢复证据，不是装备写权限。
- 继续沿用明确确认、修订绑定、审计及恢复意向防重；重复投递仅查询。不会重发退出信号或原停止命令。

最小验证：3个参数化场景使用隔离数据库和合成服务，通过完整出站队列、恢复完成、冻结解除及重复投递检查；没有在生产停服或发放测试奖励。尚未覆盖**只有部分组件退出**、冻结前后但未完成退出、容器身份变化、损坏日志，以及未能证明结果的启动意向；这些不会被显示成可自动完成的恢复。

旧版本不识别新增事件 `window-abort-intent` / `window-not-issued`；有活动维护或此类历史记录时不可直接回滚到旧代码继续管理维护记录，应使用保留新事件读取能力的兼容版本。审计和原计划不能删除来规避兼容检查。
