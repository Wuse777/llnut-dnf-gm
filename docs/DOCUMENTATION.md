# 文档维护约定

## 信息架构

- **README**：项目定位、真实界面、功能边界、使用入口；不堆叠私人生产部署日记。
- **docs/README.md**：按安装、玩家、奖励、维护、运维、开发分类导航。
- **DEPLOYMENT**：当前版本按顺序执行的步骤；首次与升级分开，不把历史默认值拼成操作流程。
- **专题手册**：具体能力、数据语义、条件和故障处理。
- **releases/**：版本差异、升级要求、附件含义、已知缺口与验证范围。
- **reports/、history/**：带日期的事实记录，不能把历史检查冒充最新验收。

## 内容与图片规则

1. 每项能力区分实现、接口检查、数据库提交和游戏客户端效果。
2. 图片使用真实前端＋合成数据；新布局截图不能冒充线上已部署。
3. 保留缺图说明；图片链路可用不等于已经分发匹配客户端素材。
4. 示例使用占位主机，不写管理员密码、生产 IP、私钥或真实玩家。
5. 相对链接、图片路径、命令参数与仓库工具保持一致。历史归档搬迁后修复相对路径。
6. 单独说明 source、静态网页与完整本机构建目录的区别，不把附件包装成一键游戏整合包。
