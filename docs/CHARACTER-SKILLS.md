# SP／TP技能点维护

角色详情 → **维护与排查 → 技能与SP／TP**。输入的是修改后的剩余点数，不是增减量。

## 范围

- 当前清风1031程序与PVF版本，PvE技能树一、二的剩余SP和TP。
- 原生 `DB_LoadEtc::GetUserSkill`／`DB_SaveSkill::SaveSkill` SQL及 `SkillSlot` 访问函数核对了映射：SP为 `remain_sp`／`remain_sp_2nd`，TP（原生SFP）为 `remain_sfp_1st`／`remain_sfp_2nd`。
- SP范围0–1,073,741,823（原生升级路径的SP上界），TP范围0–2,147,483,647（原生有符号整型范围）；不是物品数量限制，原有物品发放规则不变。
- 不清空已学技能，不返还已用点数，不修改洗点、技能指令、公平决斗存档，也不改角色等级／职业。实际清空／重建技能请使用同页上方的[已学技能重置](CHARACTER-SKILL-RESET.md)；等级／经验使用[关联维护入口](CHARACTER-PROGRESSION.md)。这三个入口独立预览、提交和审计。

## 操作

1. 管理员在「功能与权限」开启「SP／TP技能点维护」；新安装默认开启，现有实例可直接网页切换，不需要SSH启用。
2. 在「维护中心」显式开启维护窗口。此操作会按既有维护流程退出游戏组件，应自行选择维护时机；打开技能点页不会停服。
3. 刷新技能存档，修改所需项目、填写原因，生成预览。
4. 核对UID、角色号、变化前后点数后确认。没有变化的字段不加入修改请求。
5. 请求失去响应只查询原编号，不重复提交。结束维护后由游戏加载存档。

## 一致性与部署

- 复用存档预览、维护许可、防重意向、同连接事务、快照、审计和中断核对；不增加管理库迁移。
- 签名绑定账号、角色、版本、职业/等级/当前技能树及技能存档摘要；确认前重读，变更后需重新预览。
- 技能BLOB仅计算摘要和长度用于变化校验，不解析／清空／覆盖。只获得固定四个点数字段的UPDATE列权限，无INSERT/DELETE或整表写权限。
- 不跨用装备或通用业务确认接口。缺失技能记录不自动补造。
- 最小验证使用本地隔离MySQL5.7合成记录；不对生产玩家执行技能点修改，不要求客户端配合。数据库成功不表示客户端效果已验证。
