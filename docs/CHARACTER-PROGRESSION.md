# 角色等级与经验关联维护

## 网页入口

角色详情 → 维护与排查 → **等级与经验**。上方仍是只读核对，下面是「调整等级与经验」。功能与权限中的「等级／经验维护」开关可由唯一管理员直接开启，所有未删除角色均可选；无额外测试账号白名单或SSH启用要求。新安装默认开启，既有实例需在原策略中显式添加，部署状态见实施台账。

写入须先在维护中心显式开启维护窗口，完成后关闭窗口由游戏加载。打开本页、开功能权限或生成普通页面查询不会停服。维护流程仍不触碰mihomo、cliproxyapi或共享Docker。

## 会修改什么

- 选择目标等级；累计经验留空时取对应等级起点，也可填写该等级PVF区间内的无符号经验。数据库有符号负值按相同32位数据保存，不视为负经验。
- 同事务更新 `charac_info.lev/exp`、`charac_stat.exp`、已确认的成长属性及两套剩余SP／TP，快照、防重记录、成功审计一并提交。
- 成长采用当前职业的原生成长基线差额：当前属性 + 新等级基线 − 原等级基线。保留原存档中非等级获得的额外属性，不把整个属性重置为PVF初值。
- 成长基线按原生 `InitializeCharacStat`：1–14次升级使用未转职成长，15–49使用转职成长，从50起使用当前觉醒成长；不是将最高成长率乘全部等级。
- 属性存档单位沿用原生导入：float32(value×10)，半值远离零取整。`STRDCharacterStatus::Clear` 已确认将省略属性初始化为0；按段解析，不使用会合并重复标签的通用fields方法。
- SP／TP按已核对的原生管理员 `SetCharacLevel` 公式，而不是普通逐级升级奖励总和。SP为等级差×端点等级的SP值并按原生上下界截断；该程序 `GetSpAtLevelUp` 只接受1–95，超出范围增量为0。TP遵循原生49／50级分支。所有变化均在预览显示，可另用SP／TP页设置所需剩余点数。
- 仅修正同等级经验时不重新归一化技能点。

**不修改**职业／转职、已学技能BLOB、指令、已用技能点、洗点、公平决斗、任务完成状态、物品或金币。不模拟升级活动、任务奖励、金币补贴、工会通知等原生在线事件；不是调用游戏进程的在线升级。职业修改与技能重置仍是独立未完成功能。

## 规则索引与兼容性

适配程序SHA-256：`8859c99d8290dc5fb58151444138cf2697b2bfff12d47d6159596a03f20b5261`。维护电脑运行：

```bash
PYTHONPATH=src:tools python tools/enrich_catalog_growth.py current-catalog.sqlite Script.pvf new-catalog.sqlite
```

输入为当前索引精确副本，PVF哈希须匹配，输出必须新文件。仅增加 `progression_growth`、`progression_sp` 和成长版本元数据；不改变物品许可、数量规则、任务、附魔、图片及经验阈值。当前资源提取11职业、181成长组合、200个SP等级值；SP表项存在不代表原生查询范围延伸到200级。原始PVF、真实SQLite和私有反汇编不进入Git。

原经验表来源 `character/exptable.tbl`，99个累计阈值对应2–100级。它是PVF参考，不宣称运行时最高等级或已排除所有插件影响。缺失下级阈值时只可用已知本级起点，不伪造下级范围。数据库字段溢出、缺失职业成长或异常抗性存档会给出具体原因，不截断或破坏存档。

预览签名绑定完整关联存档、已学技能指纹、成长规则摘要、目标与版本；确认重读并锁定关联InnoDB记录。两处经验、属性及技能点任意变化均须重新预览。未知提交只查原操作编号，不自动重发。快照不是装备61字节格式，不混用装备恢复接口。

## API 与检查范围

`/dnf-gm/api/v1/character-levels` 下提供角色读取、预览、确认、取消预览和历史／原编号查询。原只读 `/characters/{id}/progression` 保留。

本批仅3项纯算法检查、2项隔离MySQL5.7关联事务检查、1项前端交互检查及构建；包含同编号防重、陈旧存档拒绝、提交前异常回滚、保留技能BLOB及额外属性。不运行全量测试，不对生产玩家写入，不用数据库成功冒充客户端效果。部署与公网只读检查结果另记实施台账。
