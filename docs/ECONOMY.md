# GM 发放统计与核对

状态：第十五批本地开发，尚未发布或部署。生产状态与游戏效果不由此文档确认。

## 范围与使用

“发放统计”只汇总本后台成功审计里的点券、代币券、积分、邮件金币和道具，不读全体玩家余额计算所谓经济总量，也不包含打怪、交易、商城消费或其他GM工具。所有报表为只读，不提供撤销、回收或绕过发放流程的入口。大额和多次补偿只是人工核对线索，不新增奖励额度限制，不自动处罚玩家。

1. 在导航选择“发放统计”，选北京时间起止日期（含结束当日，最多31天），可输入一个UID；默认近7天。
2. 先看“统计覆盖情况”。只要有未导入或内容不完整的审计，金额就是**已解析小计**，不是完整总计。不能把未知金额按0补齐。
3. 查看每日、物品、账号、礼包版本、原因或操作明细。物品最多50项，账号/礼包/原因最多20项；排行不是全部记录。金额以十进制字符串传给页面并用BigInt格式化，避免超过JavaScript安全整数后失真。
4. 修改筛选表单不会立即改变已展示的结果或导出范围；点击查询后才应用。报错就近展示，查询失败删除旧统计，不把旧值当作新结果。
5. 邮件积压和补偿核对按需载入，无后台轮询。可跳转原操作、玩家中心或问题工作台。

同一奖励里重复物品合并数量，不同PVF版本分开统计；物品名称来自当次奖励快照。账号“每账号一次”奖励按真实提交结果计数，第二个角色没有再次领取的货币不重复计入。邮件金币按整封邮件一次计入，不乘附件记录数。每日扣减为正的扣除额，净变更为带符号的发放减扣除。

## 数据与原子性

011迁移新增 `dnf_gm.economy_operations` 和 `dnf_gm.economy_values`，均为InnoDB。成功奖励审计、金额/道具统计投影、游戏业务写入与幂等结果使用同一连接同一事务。普通和批量/定时奖励均接入；投影失败则奖励事务回滚。运行账号对投影表仅SELECT/INSERT，不授予UPDATE/DELETE，不增加游戏表权限。

投影金额取成功结果中的before/after及冻结邮件奖励，不使用请求里的预期变化值猜测。源审计指纹与操作编号保持不可变；同编号相同来源重复导入不重复计数，不同来源拒绝覆盖。记录不完整历史时保留操作及原因，不制造推测金额。

## 历史导入

升级不会自动扫描和导入全部审计。由维护者在正确实例、正确配置下按有界页执行：

```bash
DNFGM_CONFIG=/etc/dnf-gm/config.json PYTHONPATH=src \
  /opt/dnf-gm/venv/bin/python tools/import_economy_history.py --after-id 0 --limit 50
```

路径按实际安装调整；从应用源码目录执行。每页最多100条，每条使用独立小事务，只写统计投影、不发奖励。保存返回的 `after_id`，下一次传入该值；`has_more=false` 表示此轮扫描结束。重跑旧页不会重复发奖或重复计数。若中途失败，重跑该页以核对已提交条目，不能直接跳过未知范围。需要限制总运行时间时分次执行，不在生产持续无界循环。

邮件积压依赖004邮件台账；历史奖励统计导入**不替代** `tools/import_mail_history.py`，见[第一批邮件流水说明](reports/MANAGEMENT-EXPANSION-01.md)。缺少投递台账、未记录附件、丢失游戏邮件行分别显示。数据库领取、删除标记不等于客户端实际领取验收，缺失记录不判为已领取。

## 接口与导出

认证路径前缀 `/dnf-gm/api/v1/economy`：

- `GET /summary`：覆盖率、总计/小计、每日及排行。
- `GET /operations`：每页50笔，按审计编号游标分页；可选大额筛选。
- `GET /backlog`：所选投递日期内的当前领取标记与最早20条未领取附件。
- `GET /compensation`：全历史补偿超过一次、所选日期有关联投影的前20个问题。
- `GET /export`：NDJSON，只导出已应用日期/UID范围，不继承页面“大额”筛选。

所有接口要求已登录并限速。日期按Asia/Shanghai转换到UTC查询，结束日包含整天。交互分页的 `upper` 是最大投影编号而非审计编号，以排除后来导入的旧审计；交互请求不是跨请求数据库快照，需刷新查看并发新增。

导出使用一个Repeatable Read一致性快照，50笔一页，最多占用现有3个连接中的1个，不新增连接池。HTTP下载整体有120秒上限（包括慢客户端），失败或断开显式关闭生成器和连接；查询本身仍受MySQL超时约束。首行metadata注明范围与快照，末行必须是 `type=complete` 才证明已投影快照遍历完成；出现 `incomplete`、缺末行或网络中断均不完整。**complete不证明全部旧审计已导入，也不证明游戏内效果。** 不在网页内一次加载整个导出文件。

## 安装、回滚与资源

前置迁移001–010及其最小授权必须存在；按[部署说明](DEPLOYMENT.md)安装011。新安装bootstrap包含011。当前合并版健康检查要求001–011，缺迁移不能先切换应用版本再期待写操作可用。

不增加常驻进程或后台轮询，不调整192MiB/25%CPU总预算、3连接上限或现有奖励数量边界。报表有日期、分页、查询时间与排行上限，生产仍须低强度测量实际成本；本地通过不等于生产性能达标。

回滚应用保留统计、审计及幂等记录；不删除011或回滚已发奖励。旧版应用产生的新奖励没有投影，重新升级后需补导历史，覆盖情况将提示缺口。统计投影是派生数据，不是修正已发奖励的工具。
