# 卡死位置救援（清风1031）

入口：**账号与角色 → 查看详情 → 位置救援**。唯一管理员可在「功能与版本」切换 `char-rescue`，安装/本次部署直接启用，范围为全部账号。无需SSH逐次授权。

## 功能与边界

将 `taiwan_cain.charac_info.village`、`taiwan_cain.charac_stat.village` 和 `village_prev` 同步重置为 **1**。这是固定镜像原生加载检查使用的默认回退城镇；当前匹配PVF的 `town/town.lst` 将1映射至 `Elvengard.twn`，名称为艾尔文防线、最低等级1。

本功能用于修复持久城镇选择异常，不是在线瞬移，不写入任意XY坐标，不清除任务、最近地下城记录、疲劳、经验或物品，不承诺修复客户端资源缺失、任务异常、网络掉线等其他原因。三个值已是1时提示无需重复写入。名称和地图布局随PVF变化，不将当前地图名字视为跨版本常量。

## 网页操作

1. 选择目标角色并打开「位置救援」，核对账号、UID、角色号和三个当前城镇编号。
2. 在维护中心明确开启维护窗口。查看资料不自动停服；实际写入不是在线热更新。
3. 填写原因，生成预览，确认目标与修改前后编号。
4. 成功后关闭维护窗口、恢复游戏组件；玩家重新登录时加载存档。界面数据库成功不等于已验证游戏客户端效果。
5. 超时后只查询原操作编号；不自动重复提交。历史、不可变快照、原因和审计均保留。

## 实现依据与事务

只读核对了当前MySQL字段类型、默认值及原生程序 `DB_LoadCharac::_getCharacStat`、`Inter_LoadEtc::verifyCharacVillage`；后者在城镇不存在时调用 `setCurCharacVill(1)`。当前程序SHA-256：`8859c99d8290dc5fb58151444138cf2697b2bfff12d47d6159596a03f20b5261`。程序、PVF与反汇编未进入Git。

复用既有维护租约、持久执行意向、事务及中断核对。快照格式 `qf1031-location-1`、容器 `character_location`，不是物品槽位。预览绑定角色归属、全部位置字段、版本和维护窗口；条件更新与完整after-image复核后，快照/审计/结果同事务提交。原通用充值、装备、疲劳及改名入口不能确认救援操作。

运行账号仅新增三个城镇列所需的SELECT/UPDATE权限，无游戏表结构变更或通用SQL接口。安装/升级授权已同步；无需新增管理库迁移。回退不识别该动作的旧版前先关闭网页 `char-rescue` 开关，保留审计与快照；应用回滚不自动撤销成功救援。

## 最小验证

- 隔离MySQL5.7两个定向用例：三个字段原子更新、经验/疲劳不变、重复确认原结果、已复位拒绝无意义写入、事务失败全部回滚。
- 一个前端用例：就地原因提示、目标/接口正确、响应丢失不重复提交。
- TypeScript及生产构建。生产只读页面/接口检查，不为测试开启维护窗口，不对现有玩家救援；游戏内效果未实测。
