# 外观 v2：实际部件与动作

外观工作区读取角色数据库存档，解析透明装扮的有效显示物品，再按私有部件库合成。支持的动作分别列出；没有素材或没有核实的规则不会用默认衣服替换。预览始终说明尚未覆盖的武器效果、职业附加层、光环和隐藏开关，`complete=false`、`client_verified=false`。

页面提供待机、行走、已适配的普通攻击片段、播放／暂停、逐帧和左右镜像。左向按钮明确标为“镜像”，不声称来自另一组客户端方向帧。窗口隐藏、页面离开或缓存失活时停止播放；全局只有一个预览持有播放租约。系统减少动态效果设置会停在静态帧。保存和应用外观方案只作用于 GM 偏好与本地试衣，不修改玩家穿戴。

## 实际存档与透明关联

规则绑定服务端程序 SHA-256 `8859c99d8290dc5fb58151444138cf2697b2bfff12d47d6159596a03f20b5261`。原生证据见 [首帧说明](CHARACTER-APPEARANCE.md#实际穿戴存档读取与原生证据)。v2 按同一角色、所有者与未删除状态读取 `slot=0..114 AND stat=0 AND expire_date>NOW()`，最多读取 116 条以发现超过已核实 115 个区域位置的异常。

`clear_avatar_id` 是实例关系，不是物品编号。它只能在同一次有效加载的背包区域 `10..114` 中按 `ui_id` 唯一解析。穿戴区域 `0..9` 的实际显示优先使用该关联物品。重复槽位、重复实例、悬空关系、来源不在背包、嵌套透明关系、来源染色、未知或冲突 PVF 部位均有独立原因码。原始与替代物品必须具有相同的精确 PVF 部位。

v2 增加 `ui_id` 列的 SELECT 权限，其余读取列沿用 v1。没有相应权限时仅外观区域不可用。实例编号和账号／角色身份不会写入图片配方、前端绘制清单或公开仓库。精确 `[aurora avatar]` 单独保留在外观摘要中并标为尚未绘制，允许其余已确认部位作为部分预览展示。

## 部件库与动画

维护电脑离线解析匹配的 PVF/NPK，运行服务只读 SQLite、PNG 和规范存档配方。`appearance_recipe_version=2` 与旧首帧摘要独立，保留基础职业、规范化成长代码、实际显示部位物品、两个染色标识、武器和光环身份。未穿戴的部位才可使用同职业默认部件；实际穿戴物品在库中缺失时，不能静默换成默认物品。

每个部件独立使用 EQU 的职业块、variation、图层顺序，以及 LAY 的动作引用。身体与衣服各自解析 ANI 图像帧、位置、延时和循环，再合并时间边界。不会使用身体帧号代替衣服帧号。跨帧固定脚底锚点，空图像帧仍保留持续时间。

限制为每动作 120 帧、10 秒；512×512 角色画布、锚点 `(256,448)`；每张图集最多 2048×2048；单动作使用的解码图集不超过 64 MiB。浏览器校验图集摘要、尺寸和清单，采用受预算约束的共享缓存。图集使用独立清单和受会话鉴权的 `/assets/<PVF>/<SHA>.atlas.png`，没有放宽原有图标的 512px 边界。

未知 ANI 参数、坐标模式、非恒等缩放／旋转／翻转／裁剪、无法证明的局部循环和身体／装备时间线不匹配均拒绝对应动作。对于独立且已识别为非零 `GRAPHIC EFFECT` 的特殊图层，可以省略该效果层并把部件标为 `partial`；保留的基础层仍来自实际物品。界面明确列出“已绘制时装基础层；特殊发光／混色图层尚未绘制”，不按普通 Alpha 猜测混合结果。没有任何可支持基础层的武器仍标为不可用。

`attack` 指 CHR `[attack motion]` 的首个站立普通攻击片段，不涵盖完整连击链、职业技能、变身、命中判定、伤害或实时战斗。没有该映射的职业不提供攻击按钮。

## 生成新的私有包

Windows 使用 PowerShell 7+。输出必须是新目录；不要对活动素材包追加或原地覆盖。

`--source-pack` 可以是基础图标／首帧包，也可以是已有 v2 包。不传 `--animations` 时，继承完整 v2 表并逐一验证和复制注册图集；传入 `--animations` 时，只在新输出目录中清除继承的 v2 表与元数据，再用完整显式物品列表重编，不继承旧动画索引或图集。源包保持不变。独立头像合并入口使用相同的图集与清单校验逻辑。

```powershell
python tools/build_character_assets.py --pvf E:\private\Script.pvf --npk-dir E:\private\ImagePacks2 --source-pack E:\private\assets-old --output E:\private\assets-new --animations --avatar-items E:\private\visual-item-ids.json
```

`visual-item-ids.json` 是最多 20,000 个明确的时装或武器物品编号组成的数组。默认部件与显式物品记录分别保存；编译器不枚举所有衣服组合。v1 图标、插画和默认首帧保留，v2 追加 `appearance_parts`、`appearance_atlases`、`appearance_dye_colors` 表及 `atlases/<SHA>.png`。私有诊断可能含逻辑路径，只能保留在维护电脑。新包整体上传、核对摘要后切换配置；公开 Release 仅发布程序和文档。

## 已证明与待证明

2026-11-09 的只读实例快照含 30 条有效穿戴记录，其中 16 条带透明关联、0 条带染色标识。六个未删除角色的规范配方均可解析；三个穿戴九个基础时装部位，另外三个未穿戴时装。配方解析成功仍须逐动作核对部件库和游戏画面，不能等同于完整像素一致。

本轮私有部件库显式输入 129 个物品编号（含六个实际武器编号），生成 729 条部件动作记录：536 条基础层完整、56 条省略独立特殊效果层、137 条不支持；另有 387 张注册图集和 36 条颜色记录。数字是部件／动作数量，不是完整角色或全客户端覆盖率。旧版默认首帧 11 张与 29,206 个既有 PNG 保留，没有加入实际整套 v1 配方或示例服装。

实际六套配方均标为 `partial`，职业附加层、光环和隐藏开关等具体限制保留在 API 与页面中。源码层面的针对性核验为 47 个后端测试与 3 个 renderer 测试通过，覆盖实例关联、透明来源、ANI 时长、独立时间边界、缺失实际部件拒绝、特殊层省略、基础武器、私有包 v2 继承／重建与流式图片大小预算。这些测试不代替客户端画面对照，也不代表本轮运行了完整 CI。

- **透明关联：已实现。** 只接受上述明确的同角色背包实例关系；当前两套实际配方使用该能力。
- **染色查表：已提取。** 当前 PVF 的 `etc/avatarcolorvariation.etc` 含 36 个颜色 ID／RGB／名称记录。固定原生程序的 `AvatarVariation::importAvatarColorVariation`（`0x088d444f`）按 ID 查表存储 RGB，仍未提供客户端混色公式。ID 0 的含义不能按颜色表中的绿色直接着色。
- **染色像素：待核实。** 客户端 `_mask1` 资源已找到，但掩码通道、亮度保持、混色公式和透明覆盖后的优先级尚未证明。非零染色继续返回 `dye_pixel_rule_unverified`，不会直接把 ID 当 RGB 或 variation。
- **基础武器：按部件能力提供。** 从实际武器 EQU/LAY/ANI 编译可支持图层；强化、幻化、光剑特殊效果等未完整覆盖时分别说明。
- **职业常驻层：待核实启用规则。** 已定位 growtype EQU/ANI/IMG，例如剑魂手臂、狂战士与战斗法师图层；仅凭文件名不能证明当前职业／觉醒应启用的组合与可见开关。
- **精确头像：独立映射。** 头像不从纸娃娃、时装包名或素材排列顺序推断；沿用显式 `job/grow_type/sex` 映射与基础插画回退。

实际画面对照应覆盖普通服装、透明替代、各染色通道、特殊图层、基础武器和逐动作锚点。未对照前不能宣称客户端一致性验收完成。
