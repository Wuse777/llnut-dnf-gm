# 维护期间普通游戏写入冻结

2026-11-05，第二十七批开发版。已在本地接入应用写入口、任务执行器和网页状态；**未部署，完整网页停服／恢复调度器仍未完成**。此模块不是另一个管理员权限开关，不替代整个实施台账。

## 为什么需要它

装备维护不能只停止游戏进程：GM充值、邮件、提前解锁、批量奖励或原生控制指令也可能正在执行。本模块让未来固定root协调器先冻结新的普通游戏写入，并等待当前应用持有的写租约结束。它不停止服务、不重启Docker、不修改奖励数量限制。

管理员的能力开关仍由“功能与版本”网页管理。维护冻结只是有明确生命周期的临时互斥状态；“全部开放权限”不能让普通写操作和存档维护同时进行。最终完整执行器应从网页维护申请自动冻结并在已证明恢复后自动解除，不要求管理员日常SSH改配置。

## 已覆盖入口

| 入口 | 冻结时行为 |
|---|---|
| 点券／代币券与组合奖励确认 | 不改余额、不发邮件；原预览保留，恢复后需重新核对有效期与余额 |
| 邮件、金币附件、封禁／解封 | 新确认被拒；已提交的同键原结果仍可查询 |
| 单角色／批量提前解锁 | 不改任何锁记录，批量保持原子性 |
| 公告、踢人、封禁联动 | 不提交新的发送意向、不发网络包；已认领的原操作不重发 |
| 批量奖励执行器 | 不认领新目标、不增加尝试次数、不把正常等待写成失败；已有不确定目标仍可核对 |
| 定时计划执行器 | 先核对已有期次；冻结期间不创建新期次或子任务。恢复后沿用原有超过5分钟跳过规则，不自动追补旧期次 |
| 账号／角色／审计／结果查询及管理配置 | 保持可用；配置变更仍遵守自身权限和并发校验 |

恢复后不是重新授权或自动重放原请求。单次操作仍受原有效期、目标与余额变化校验；批量及定时工作遵守其持久状态与防重规则。

## 文件协议与锁顺序

固定安装目标为 `/var/lib/dnf-gm/write-gate`；应用设置为 `gameplay_gate_dir`。路径空仅用于未安装该机制的旧版本兼容，不提供完整维护能力；配置非空时缺文件、权限异常或内容无效一律拒绝新游戏写入。

- `fence.lock`：root创建的稳定inode，应用只读打开并取得共享锁。
- `state.json`：root原子写入的持久状态，包含open/frozen、generation、原维护编号、目标身份摘要和时间。
- 状态和目录拒绝符号链接、不安全属主/权限及不可信文件；提交前再次核对锁inode及完整状态。
- 冻结使用非阻塞独占锁，已有写租约未结束时返回busy，不假装冻结成功。
- 应用租约覆盖数据库提交、回滚／连接关闭；原生控制还覆盖实际网络发送及结果记录。
- 重启、过期、网页刷新和权限切换均不自动解除冻结。
- 解除要求当前完整token匹配，并由固定协调器完成恢复证明；不能把网页传入的布尔值用作恢复证明。
- 安装／回滚检查在冻结或状态无法核验时拒绝切换版本，避免丢失原维护所需的代码。第二十八批预检同时检查固定路径和既有配置路径；安装器自动配置上述固定目录，不静默切换已有的不同路径。

`deploy/maintenance_gate.py`目前是root协调器的底层原语，没有独立可执行CLI或已安装服务。`release(token, verify_restored)`的回调接口尚待完整协调器接入；隔离测试中的True回调不是线上恢复证明。

## 网页和任务健康

维护中心显示“普通写入已开放／维护冻结中／状态未知／未安装”，冻结时展示原维护编号，并说明历史查询可用。不提供无证据强制解除按钮。

任务异常中心冻结时不把预期的排队等待和未触发计划误报为停滞，但继续显示真实失败、提交待确认、长时间执行、未核对期次和工作器故障。恢复后重置连续进度观察计时。状态在读取期间变化或不能核验时，不返回“全部正常”。

## 第二十八批：MySQL事务排空

新增013管理迁移，固定InnoDB表`dnf_gm.gameplay_fence`的`id=1`行。配置了持久文件屏障的普通写事务在写游戏前执行`LOCK IN SHARE MODE`，持锁直至该事务实际提交或回滚。批量奖励在持久认领提交后、真正奖励事务开始时重新取得共享锁，不能假定上一事务锁还在。单次奖励、处罚、解锁、原生控制认领和定时新派发均已接入；共享锁允许多个正常事务并行，不将所有充值串行化。

root的`WriteGateManager.drain_database(token, db, expected_server_uuid=原计划实例UUID)`验证原冻结token、原计划数据库实例UUID和固定配置绑定，在持有文件共享锁的情况下对同一行`FOR UPDATE`。只有参与协议的旧数据库事务结束，它才取得锁并返回排空证据；查询超时、协议损坏、提交响应丢失或连接关闭失败都不会返回成功。原冻结仍保留，可按原token再次做只读核对，不重发游戏写入。证据包含数据库实例UUID和原维护绑定，且明确`maintenance_permit=false`。

这只证明**参与该协议的普通GM事务已经结束**，不证明奖励客户端效果，不替代原操作结果核对、游戏进程缓存处理、所有写入者停服或存档维护许可。其他root工具和游戏进程不受这条管理库行锁保护；完整执行器必须继续完成真实游戏退出／剩余写入者停止／关窗和恢复。

安装器自动准备文件屏障；运行账号对协议表只有SELECT，没有INSERT/UPDATE/DELETE。健康接口使用不加锁的读取核验协议，不因root持有独占锁就被误判为宕机。空路径仅用于未安装旧版兼容，不能取得完整维护能力。`release(token, verify_restored)`仍等待完整恢复协调器接入，不接受网页布尔值代替恢复证明。

## 第二十九批：接入持久维护计划

数据库排空不再只是独立原语。`DrainCoordinator`生成的v2计划包含原数据库`server_uuid`和当前开放屏障代次，并纳入确认指纹；准备前后只读检查数据库协议和屏障，拒绝在确认时换成新实例/新代次。缺少`MaintenanceAdmission`适配器只能读取已有记录，不能生成或执行新计划。

确认持久记录如下顺序：`freeze-intent` → `write-gate-frozen` → `database-drained` → 原游戏退出步骤。冻结比较在同一文件独占锁内完成；数据库证明绑定原实例、申请、代次及主机身份。每个游戏阶段写入回执前再次核对原冻结令牌。所有游戏命令仍使用固定指纹适配，不添加任意命令入口。

事务等待超时、身份变化、协议损坏或证据持久化失败时，不进入后续游戏命令。若冻结已发生则保留冻结；工作进程死亡、回执丢失或重复确认只返回原记录，不能再次发送命令。旧v1持久记录可查询/取消未开始计划，但不能直接确认；需取消后生成带数据库绑定的新计划。新协议未改变已有游戏表或增加游戏写权限。

**仍不是完整维护执行器。** 普通事务锁结束不等于原操作结果核对、游戏缓存已保存或维护窗口已建立。原生指令未决结果、剩余写入者退出、监控握手、permit签发/关窗/按原服务状态恢复还需继续接通。`PreparationWorker.execute_supported`仍为false，不会把这一阶段当作可以公开停服的完整流程；本批未部署、未连接生产、未实际发退出信号。
