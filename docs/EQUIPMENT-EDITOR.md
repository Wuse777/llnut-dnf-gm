## 网页使用

角色详情中从穿戴、背包、角色仓库或账号仓库选择“维护此物品”。编辑入口显示当前账号/角色、真实存档槽位、物品名称、图标或诚实占位、PVF部位、等级及基础耐久。PVF部位与存档位置分别展示，不推断摆放一定正确。

- 强化/锻造、增幅、耐久/数量分组；增幅类型尚未核实中文属性映射，继续显示0–4代码，不猜测。
- 附魔可按名称、编号或效果搜索，每页20条；显示名称、明确标注的部位、PVF原始效果。结果区域有界滚动，选择后自动收起；选择只填入编号，不提交游戏写操作，清除填0。手动编号入口保留，沿用当前索引识别校验，不新增“只能使用搜索结果”的限制。
- 仅明确存在完整`[enchant]…[/enchant]`定义的物品进入附魔检索；名称含“宝珠”或路径含`orb`不构成附魔证据。效果未知标签原样保留，速度等数值不冒充已换算百分比，部位不是完整适用性保证。
- 预览并排显示修改前后、附魔名称和效果，同时保留准确的变更字段清单与完整原始字段。品级原始32位字段折叠在高级区域；输入错误会展开并定位，不能当作0–100%的品级输入。
- 当前附魔名称/效果也显示在角色装备/背包/仓库物品详情中。未知编号明确未识别，不假装无附魔。

管理员登录即可读取，不新增权限开关或仅测试账号限制；既有装备编辑/回收/恢复沿用网页功能开关和显式维护窗口，不会因为查看物品自动停服。不改变数量1–2,147,483,647、不按PVF堆叠上限限制，邮件金币仍最多10亿。

## 索引与接口

离线处理维护电脑上的私有PVF，不在服务器解析完整文件：

```bash
PYTHONPATH=src python tools/enrich_catalog_equipment.py current-catalog.sqlite Script.pvf new-catalog.sqlite
```

要求PVF SHA-256与当前索引一致，输出必须为新文件；原有items（含原始策略）、任务、经验、职业及其他表保留。只追加/更新`equipment_details`、`enchantments`、`equipment_index_version=1`和本次提取失败数。不能用旧基础索引覆盖当前服务器索引；安装前核对当前完整SHA并备份原文件。索引和游戏素材不进入Git。

`GET /dnf-gm/api/v1/catalog/enchantments?q=名称或编号或效果&page=1`，登录后只读；物品与角色详情沿用现有接口。没有该索引的旧安装显示“尚未安装”，保留手动编号能力。PVF不匹配时附魔结果只读不可选择；写预览仍重新校验版本。

新预览保存文字语义信息，供原编号查询和审计；不在确认事务中附加易变的图片包状态。旧记录仍可按原编号查询；跨版本未完成预览如校验不符，须取消后重新读取，不自动确认或重放。
