# 角色改名（清风1031、当前三服适配）

入口：**账号与角色 → 查看详情 → 角色改名**。唯一管理员在「功能与版本」管理 `char-rename` 开关；当前部署直接启用、允许全部账号。没有SQL/Shell输入框，不需要每次SSH授权。

## 使用流程

1. 选定角色，页面显示账号、UID、角色号、当前名称和关联记录数量。
2. 在维护中心显式开启维护窗口。改名不是在线热修改；查看本页不会自动停服。
3. 输入新名字和原因，生成预览，确认新旧名字及目标后提交。
4. 响应超时时只查询原操作编号，不自动重复确认；结束维护后游戏组件重新加载名称。

客户端名字按UTF-8字节通过MySQL latin1映射写入，保留0x81/8D/8F/90/9D的MySQL特有映射，不使用会损坏这些字节的宽松转码。存档字段上限20字节，中文通常每字3字节；不允许空名、空白或控制字符。重名以数据库实际排序规则检查，已删除角色占用的名字也不绕过。特殊字形是否被客户端显示不由数据库提交证明。

## 同事务范围

- 主角色名：`taiwan_cain.charac_info.charac_name`。
- 公会成员、会长和推荐名称：`d_taiwan.guild_member`、`guild_info`、`guild_recommend`。
- 代表角色名称缓存：`d_taiwan.dnf_master_charac`。
- 黑名单名称缓存：`taiwan_cain_2nd.charac_black_list`（其他账号对该角色的引用一起更新）。

跨服表仅修改 `server_id=3`，与当前游戏 `server_group=3` 和已有 `login_account_3` 适配一致，不修改其他区服同号角色。公会/代表角色的账号归属不一致时拒绝整笔操作；不会猜测归属。原生DB中间件的黑名单改名与公会名称持久化路径已只读核对；当前实例不存在 `pvp_buddy` 表，本适配不宣称支持另一套跨服PvP数据库。

历史邮件寄件人、管理审计、活动公告/广播文字等历史内容保留原样，不把所有出现旧名的文本全局替换。UID、角色号、职业、等级、物品和金币不变。

全部参与表必须为InnoDB。预览绑定完整关联快照、版本与维护窗口；确认后重读并锁定记录，修改名称、不可变快照、防重与成功审计在同一事务提交，提交前重新核对全部关联存档及改名后的目标身份。中断仍由原维护窗口的结算流程核对，不自动重放。

## 安装与回滚

新增精确名称列UPDATE和必要标识列SELECT；不修改游戏表结构，不授予任意表写权限。bootstrap和版本升级的授权生成器已加入本适配。没有新管理库迁移，`char-rename`兼容原动作字段长度。

快照为 `qf1031-character-name-1` JSON，容器类型 `character_name`，不是物品二进制槽位。装备和疲劳入口无法确认此类操作；角色改名历史独立分页。回退不识别新开关的版本前先在网页关闭 `char-rename`，保留审计和快照；回滚应用不自动撤销已经完成的改名。

## 验证边界

仅隔离MySQL5.7验证中文编码、关联更新、其他区服不变、重名/字节长度、防重与事务中途失败；前端定向验证就近提示、目标/接口与超时后只读恢复，并进行生产构建。未对现有玩家改名、未为测试停服，游戏内显示效果未实测。
