# GM 工作台与界面偏好

[文档中心](README.md) · [界面截图](SCREENSHOTS.md) · [外观说明](CHARACTER-APPEARANCE.md)

前端基于固定上游 SoybeanAdmin v2.3.0（提交 `ab40c08992807e303dd8aabb6ec43d7e2334b24f`），保留其 AdminLayout、Naive UI、主题、图标、Pinia 和工作页签体系；演示登录和令牌请求已替换为原有 GM Cookie／CSRF 协议。路由类型继续通过 Elegant Router 生成，实际注册明确的目标路由。上游清单见 [UPSTREAM.json](../web/UPSTREAM.json)，许可证见 [SOYBEAN-LICENSE](../web/SOYBEAN-LICENSE)。

## 从玩家出发

| 入口 | 主要任务 |
| --- | --- |
| 工作台 | 搜索玩家、可折叠最近与收藏、跨工作流待办，以及独立的管理库／游戏库备份入口 |
| 玩家中心 | 检索和在线视图、账号／角色工作区、问题处理、解锁队列 |
| 奖励运营 | 奖励编辑器、投递、模板、活动、批量、定时、公告与游戏控制、统计 |
| 道具与外观 | 统一选物、常用筛选、四件对比、网页外观方案、素材覆盖 |
| 系统运维 | 诊断、维护、备份与恢复演练、权限、版本检查和审计 |

账号地址为 `/dnf-gm/players/:uid`，角色地址为 `/dnf-gm/characters/:characNo`。页面恢复先读取目标，不执行变更；账户在线状态、角色状态与存档时间分别呈现。数据库存档不是实时战斗属性。

多玩家工作页签分别保存草稿。奖励草稿的 UID、角色与 PVF 绑定不能通过切换页面继承给另一目标。会话存储用于刷新恢复，退出后清理；浏览器草稿不是待执行任务。已提交但结果未知时保留原编号，继续查询原记录。

## 角色工作台与统一待办

角色默认读取轻量概览：账号／角色身份、登录表状态、12 个装备存档槽、背包占用与前 6 件物品、角色携带金币、普通疲劳已消耗值、待处理问题和近期邮件摘要。概览不预取仓库、装扮和完整维护详情；进入相应页签再读取。背包存档槽数不是已开放格数，在线玩家的数据库值也不代表实时战斗状态。

首页统一待办按玩家问题、原操作待核对、批量异常、今日计划与异常、维护与备份分组。每组最多读取 20 条，首页展示前 4 条，可进入完整列表；每条链接保留具体问题、操作、批次、计划或备份编号。页面可刷新，并在可见时每分钟更新；旧快照不能作为任务已完成的证据。

批量详情可以按成功／失败／待核对等目标状态，以及具体错误类型筛选。待核对的目标应查看原操作编号，不能据连接超时认定失败或直接重发。

## 选物与奖励

名称／编号、类别、部位、品级、等级与排序共用筛选组件。新增职业、武器类型和套装条件只使用已收录元数据；品级 0 是有效值。最多四件装备比较来源明确的基础属性原值，不计算伤害或推断隐藏效果。

“查看详情”“加入草稿”“加入对比”和“试穿”有独立入口。常用筛选可保存到管理库，修改冲突需重新读取；旧浏览器条件可显式导入。PVF 改变后不自动迁移收藏或条件。批量策略冻结完整服务端条件，分页列表不代表冻结的全部目标。

目录默认使用紧凑列表，桌面行高 56px、手机 58px。行内保留物品信息与加入动作，收藏、比较放入更多操作；高级条件、常用物品和发放策略移入抽屉。桌面选物与奖励草稿并排。手机首次打开空草稿先显示物品搜索；已有奖励、预览或待核对操作时保留草稿页。选好玩家后显示一行身份摘要，点击“更换目标”再展开选择器。加入清单不会发放奖励。

奖励页面沿用邮件、模板、批量与定时各自的后端执行语义。修改目标或奖励后旧预览失效；确认面板一次只显示一份。服务端提交不确定时只查询原操作，重新登录或刷新不会自动重发。

## 按玩家问题排查

问题详情中的“开始场景排查”提供奖励没到账、卡地图、装备异常、任务卡住四种核对清单。可以在同屏查看当前角色概览、原奖励操作、锁定当前目标的邮件附件和已有处理时间线，再进入相应维护动作。复制清单只填入未保存的处理记录，仍需明确保存。

奖励证据分别呈现后台提交状态、数据库附件／领取标记和客户端反馈。原操作或邮件若属于其他账号／角色，界面拒绝混入当前排查。不存在邮政记录不等于玩家已领取，也不自动生成补偿。另建奖励草稿必须重新核对目标、预览并确认。

邮件中心支持历史目标名称、物品编号、礼包来源、投递日期和领取标记筛选；投递日期按北京时间解释。批次摘要与标记筛选只核对每批最新 200 条已记录附件，界面标明采样范围与是否还有更多；附件详情仍可逐页查完整记录。历史未记录附件、数据库记录缺失、已删除标记与领取标记分别展示。

维护入口采用游戏动作表述，例如“恢复普通疲劳”会在预览中解释把已消耗值改为 0。位置救援、任务、装备和解锁仍沿用已有权限、维护屏障、预览确认与审计，不通过问题清单自动修改游戏。

## 活动固定奖励与人群

`/dnf-gm/rewards/campaigns` 将固定礼包版本、目标条件、批次、计划、发放操作和统计关联到一个活动。活动启用后冻结奖励与人群；暂停后阻止新的发放，修改奖励或名单应另建活动。批量和计划携带活动编号，不能在执行时偷偷替换礼包或扩大人群。

每活动可选择按账号或按角色去重。领取记录与奖励、经济记录、邮件及活动关联在同一事务中提交；不同批次和计划共享该规则。成功提交表示数据库已接受完整奖励，不等于客户端已领取。统计同时保留去重对象与奖励合计，关联记录分页查看。

回退到不支持活动的旧版本前，兼容检查会拒绝已有活动绑定的原操作、批次和计划，包括仍能复制的历史记录；不能通过回退绕过跨批次去重。未结束或待核对的游戏备份请求也必须由兼容版本继续处理，不能通过删除记录解除限制。

角色创建日、最后游玩存档和账号备注标签可作为人群条件；日期字段类型及只读权限必须实际探测通过才可使用。回归条件采用两处最后游玩存档的较新值，并要求登录表明确离线；零日期未知。角色创建日期不是账号注册日期，不推断该镜像尚未适配的账号注册时间。

## 游戏恢复点与管理库备份

`/dnf-gm/system/game-backups` 单独展示游戏全库备份、加密异地副本和隔离恢复演练三个证据状态。某一步成功不能替代其他两步；历史成功必须对应同一个备份文件的 SHA-256，新的失败也不能抹去该文件先前的有效收据。

创建恢复点需要先进入维护中心开启维护窗口，按运维流程停止游戏并核验，再预览备份范围、填写原因并确认。网页不会自动停止游戏，也不提供生产恢复按钮。连接不确定时保留请求原编号，只查询原请求；复制与演练也使用独立原编号恢复状态。

执行器必须先由运维配置固定业务库范围、固定加密接收端和独立的同版本 MySQL 演练实例。未配置或状态过期会明确显示。完整配置、权限和恢复步骤见 [游戏恢复点说明](GAME-BACKUP-DESIGN.md) 与 [部署指南](DEPLOYMENT.md)。GM 管理库备份继续单独展示和验证，不能作为玩家存档恢复点。

## 外观与品牌

默认视觉采用暖白／石墨灰双主题与少量琥珀金。游戏识别来自装备槽位、真实物品图标、品级色及详情卡；业务页面收敛装饰，手机隐藏横幅。登录与品牌区域保留原创地下城徽记和私有包提供的职业插画。图片由受鉴权接口读取，缺图时明确降级；职业插画不冒充当前角色穿戴。

右上角主题设置保留 SoybeanAdmin 配色与布局选项，并提供 GM 密度和背景显示设置。“保存到管理库”保存当前主题、布局、侧栏、页签、密度及插画开关；“重新读取”会替换当前页面设置。写入带版本号，发生冲突时不会自动覆盖其他页面。

旧默认配色仅在颜色值完整匹配时迁移到新主题；自定义配色、布局和可访问性偏好保留。Naive UI 与业务控件使用同一组颜色和密度变量，手机标题优先保留页面名。

网页外观方案是只读试穿，不直接修改游戏穿戴。静态与动画使用同一版本化绘制清单；“当前存档”“网页试穿”“默认示意”分别标记。缺失部件或未知规则会显示具体原因，客户端一致性以实际验收为准。

## 前端分层

`web/src/layouts` 与 `web/src/store/modules` 管理模板壳层；`web/src/views/gm` 注册业务页面；`web/src/stores/gm` 分离玩家上下文、草稿、查询与操作登记；`web/src/appearance` 管理有预算约束的绘制。重型业务组件、角色画布与各页面按需加载。

原有功能权限、维护写入屏障、幂等与审计继续由服务端判断。工作页签与收藏只是界面便利，不改变游戏权限或操作提交限制。
