# 第三十批：固定写入组件退出、原状态恢复适配与只读观察

2026-11-05。延续完整十组改进和补充范围，本批推进装备维护依赖的真实组件生命周期，不代表整体交付，也不是最终UI美化。代码尚未部署；没有向生产发送退出/启动信号，没有停止或重启mihomo、cliproxyapi、共享Docker。

## 实现与修正

- 增加固定组件适配器 `deploy/service_lifecycle.py`，将原60项s6状态、原进程身份、二进制指纹和启动契约纳入维护计划。契约包含真正执行的 `run.user` / `finish.user`，不能只校验外层包装器。
- 修正 `game_*-log` 被前缀匹配误当作游戏进程的问题。MySQL、日志、s6基础组件、原本停止的可选组件保持不动；手工启动但normally-down的组件恢复原标记。
- auction / point / community 使用精确程序指纹绑定的SIGUSR2适配；不调用其危险的默认SIGKILL停止行为。其他已适配组件显式TERM退出，区分正常退出和预期TERM退出。
- 游戏排空之后依次退出剩余写入者，每条命令前持久记录意向；先禁止重启、设置down标记，再发明确退出信号。有界等待，不使用 `s6-svc -d/-k`，超时不升级强杀、不自动重放。
- 持久计划v3新增逐组件阶段和 `writers_stopped` 状态，仍不是维护许可。旧计划保持查询兼容，不暗中变更为完整组件计划。
- 恢复适配器按依赖顺序启动原活动集合，游戏之后才恢复scheduler和网关。每次启动前重新检查调用方的关窗证明，核对就绪及程序指纹，不自行释放写入冻结。
- s6控制FIFO返回不代表标志位已更新：短暂等待仅接受精确原状态或精确预期状态；出现其他变化拒绝继续。
- 新增逐组件只读观察、进程身份/信号处理/命名空间竞态核验。已确认禁止重启后回到原状态不再冒充正常过渡。
- 过渡监控在观察前后核对原冻结令牌；旧日志不能单独成为故障保护例外。期限基于原开始时间，不随刷新、重启或观察延长。
- API与维护网页显示写入组件退出阶段、剩余服务观察及TERM退出说明，不显示为“维护完成”，不增加自动重试按钮。
